## 1. ドメイン用語（登場人物・概念）

| 用語 | 英語表記／DB 名 | 定義 |
|---|---|---|
| **PR依頼者** | Client / `client` | 店舗・企業。案件（募集）を投稿する側。 |
| **投稿者** | Creator / `creator` | インフルエンサー。SNS アカウントを連携し、案件に応募する側。「インフルエンサー」とは呼ばず本書では「投稿者」に統一する。 |
| **運営** | Administrator / `admin` | サービス運営者。ユーザー・案件・通報・審査を管理する。「管理者」も同義。 |
| **案件** | Campaign / `campaigns` | PR依頼者が投稿する募集。無償提供内容・投稿者条件・応募期間・投稿期間・募集人数・ジャンル・指定ハッシュタグ・必須投稿内容を持つ。「募集」も同義だが本書では「案件」に統一する。 |
| **応募** | Application / `applications` | 投稿者が案件に対して行うエントリー。 |
| **マッチング成立** | Matched | 応募が承認され、投稿者と PR依頼者の間に契約関係が生まれた状態。この時点で 1対1 チャットが開通する。 |
| **無償提供** | Reward (in-kind) | PR依頼者が投稿者に無償で提供する商品・サービス。想定価格を持つ。 |
| **想定価格** | Estimated value | 無償提供内容の金額換算値。案件の並び順（価格が高い順）に使用する。 |
| **応募期間** | Application period | 投稿者が応募できる期間。 |
| **投稿期間** | Posting period | マッチングした投稿者が SNS へ投稿すべき期間。この期間の終了が成果レポート公開のトリガとなる。 |
| **募集人数** | Recruitment quota | 案件が受け入れる投稿者の上限人数。応募者数がこれ以下なら即マッチング、超えたら選考が発生する。 |
| **指定ハッシュタグ** | Required hashtags | 投稿に含めることが必須のハッシュタグ。ステマ規制対応の広告表記（`#PR` 等）を含む。 |
| **必須投稿内容** | Required content | 投稿に必ず含めるべき訴求ポイント・掲載必須事項。 |
| **選考** | Screening | 応募者数が募集人数を超えた場合に、PR依頼者が追加条件を加えて絞り込む工程。 |
| **条件緩和** | Condition relaxation | 応募者が募集人数に満たない場合に、システムが自動生成する緩和案（インサイト条件の緩和・応募期間の延長）。**PR依頼者が承認しない限り適用されない。** |
| **キャンセル申請** | Cancellation request | 投稿者がマッチング成立後に対応できなくなった場合に出す申請。**PR依頼者の承認が必要。** |
| **成果レポート** | Campaign report | 投稿期間終了後に PR依頼者が閲覧できる、匿名集計された実績インサイト。 |

## 2. インサイト関連用語

| 用語 | 英語表記 | 定義 |
|---|---|---|
| **インサイト** | Insights | SNS プラットフォームが提供する投稿・アカウントの分析データ。本人の OAuth 認可がある場合のみ公式 API で取得できる。 |
| **フォロワー数** | Followers | アカウントをフォローしているユーザー数。 |
| **リーチ** | Reach | 投稿を見た**ユニークな**アカウント数。 |
| **インプレッション** | Impressions | 投稿が表示された**延べ**回数。同一人物が複数回見れば複数回カウントされる。 |
| **保存数** | Saves | 投稿を保存した回数。来店・購買意図と相関が高いとされる。 |
| **シェア数** | Shares | 投稿がシェア（ストーリーズ等への転載）された回数。 |
| **エンゲージメント** | Engagement | いいね・コメント・保存・シェア等の反応の総称。 |
| **エンゲージメント率** | Engagement rate | 本アプリでは **（いいね数＋コメント数＋保存数＋シェア数）÷ リーチ** と定義する（定義は 9章で確定）。分母をフォロワー数ではなくリーチとするのは、実際に届いた範囲に対する反応率を測るため。 |
| **再生数** | Views / Plays | 動画・リールが再生された回数。 |
| **オーディエンス属性** | Audience demographics | フォロワーの性別・年齢・地域の分布。本人認可時のみ取得可能。 |
| **投稿頻度** | Posting frequency | 一定期間あたりの投稿本数。 |
| **集計値** | Aggregated metrics | 直近 7 / 30 / 90 日の平均値等、生データから算出した派生値。マッチング条件の判定に使用する。 |
| **投稿者条件** | Creator criteria | 案件に紐づく、インサイト指標を用いた絞り込み条件式。AND / OR の組み合わせで指定する。 |

## 3. 本アプリ固有の設計用語

| 用語 | 定義 |
|---|---|
| **インサイト非開示原則** | 「インサイトを条件として使えるが、実数値は誰にも見えない」という本アプリの中核制約。スキーマ分離・RPC・k-匿名性の 3 層防御で担保する（[02_system_overview.md](requirements/02_system_overview.md) 2-4）。 |
| **モザイク表示** | 投稿者が条件に合致しない案件を、詳細を隠したまま存在だけ提示する UI 表現。タップしても詳細は開かず「条件を満たしていません」と表示する。案件数が多く見えることで探索意欲を維持する目的。 |
| **案件内連番（匿名表示）** | PR依頼者に投稿者を見せる際の表示名。案件ごとに独立して「投稿者A / B / C…」と採番する。案件をまたいだ名寄せを不可能にするため、同一人物でも案件が違えば別の記号になる。 |
| **k-匿名性** | 集計結果から個人を特定できないようにするため、母数が k 人未満の場合は結果を非表示にする仕組み。**本アプリでは k = 5**。 |
| **要再認可** | SNS アクセストークンが失効し、投稿者に再度 OAuth 認可を求める必要がある状態。この状態では新規応募ができない。 |
| **二分探索攻撃** | 条件を少しずつ変えて該当人数の変化を観測することで、特定個人のインサイト実数値を推測する攻撃。件数を 5 人未満で丸めることで防ぐ。 |

## 4. 技術用語

| 用語 | 定義 |
|---|---|
| **Flutter** | Google 製のクロスプラットフォーム UI フレームワーク。本アプリのモバイル実装に採用。 |
| **Supabase** | PostgreSQL を中核とした BaaS。認証・DB・ストレージ・Edge Functions を提供。本アプリのバックエンドに採用。 |
| **BaaS** | Backend as a Service。バックエンド機能をサービスとして利用する形態。 |
| **RLS** | Row Level Security。PostgreSQL の行単位アクセス制御。テーブルの行ごとに「誰が読めるか」をポリシーで定義する。 |
| **`public` スキーマ** | クライアントが直接参照してよいデータを置く PostgreSQL スキーマ。全テーブルで RLS を有効にする。 |
| **`private` スキーマ** | **インサイト実数値・SNS アクセストークン**を置くスキーマ。クライアントロール（`anon` / `authenticated`）に GRANT せず、PostgREST の公開スキーマにも含めない。 |
| **RPC** | Remote Procedure Call。ここでは Supabase 経由で呼び出す PostgreSQL 関数を指す。 |
| **`SECURITY DEFINER`** | PostgreSQL 関数の属性。呼び出し元ではなく**関数の所有者の権限**で実行される。これにより、クライアントが直接読めない `private` スキーマを関数内部でのみ読める。 |
| **Edge Function** | Supabase が提供するサーバーレス関数（Deno / TypeScript）。SNS API 呼び出し・バッチ処理に使用。 |
| **`pg_cron`** | PostgreSQL の拡張機能。DB 内でスケジュール実行を行う。日次インサイト取得バッチのトリガに使用。 |
| **`service_role`** | Supabase の特権ロール。RLS をバイパスできるため、サーバー側（Edge Functions）でのみ使用し、クライアントには絶対に配布しない。 |
| **OAuth 2.0** | 本人の同意に基づき、third-party アプリに API アクセス権を委譲する認可の仕組み。SNS 連携に使用。 |
| **アクセストークン** | OAuth 認可の結果得られる、API 呼び出しの資格情報。有効期限があり、失効時は再認可が必要。 |
| **Instagram Graph API** | Instagram のビジネス／クリエイターアカウント向け公式 API。2024年12月に廃止された Basic Display API の後継として、現在インサイト取得に使える唯一の公式手段。 |
| **アプリ審査（App Review）** | Meta の審査プロセス。本番環境で一般ユーザーのデータにアクセスするために必須。目安 2〜4 週間。 |
| **クォータ** | API 利用量の上限。YouTube Data API v3 は 1 日 10,000 クォータ単位。 |
| **ADR** | Architecture Decision Record。アーキテクチャ上の決定とその理由を記録する文書。`docs/adr/` に格納。 |

## 5. 表記統一ルール

| 使う表記 | 使わない表記 |
|---|---|
| 投稿者 | インフルエンサー、クリエイター（UI 上の表記は別途検討） |
| PR依頼者 | クライアント、依頼企業、広告主 |
| 案件 | 募集、キャンペーン、オファー |
| インサイト | 分析データ、アナリティクス |
| マッチング成立 | 採用、当選、確定 |
| 無償提供 | ギフティング、商品提供 |
