# 5. 機能要件一覧

---

## 5-1. 読み方

【事実】機能 ID は `FR-{ドメイン}-{連番}` の形式（採番規則は [00_index.md](00_index.md) 0-4 参照）。

| 優先度 | 意味 | 扱い |
|---|---|---|
| **Must** | 初期リリース（MVP）に必須。これがないとサービスが成立しない | 初期スプリントで実装 |
| **Should** | 初期リリースに含めたいが、間に合わなければ直後のリリースで可 | MVP 後半 |
| **Could** | あると良い。初期は見送る | バックログに保持 |

【前提】「ロール」列は、その機能を**利用する主体**を表す。`system` はユーザー操作を伴わない自動処理。

## 5-2. AUTH：認証・アカウント管理

| ID | 機能 | ロール | 優先度 | 概要・受入条件 |
|---|---|---|---|---|
| `FR-AUTH-01` | 投稿者の新規登録 | guest | Must | メールアドレス＋パスワードで登録できる。登録直後は「仮登録」状態。 |
| `FR-AUTH-02` | PR依頼者の新規登録 | guest | Must | 同上。**運営承認は不要**で、メール確認と店舗情報入力のみで利用可能になる。 |
| `FR-AUTH-03` | メールアドレス確認 | creator / client | Must | 確認メールのリンク押下で「メール確認済」に遷移。未確認では次のステップに進めない。**件名・本文にサービス名とアイコンを入れ、差出人が分かるようにする**（`supabase/templates/`）。 |
| `FR-AUTH-04` | ログイン／ログアウト | 全ロール | Must | JWT による認証。停止中アカウントはログインできるが、理由を表示し操作を制限する。 |
| `FR-AUTH-05` | パスワードリセット | creator / client / admin | Must | メール経由のリセットリンク。 |
| `FR-AUTH-06` | 投稿者プロフィール登録・編集 | creator | Must | 氏名・生年月日・居住都道府県・自己紹介・得意ジャンル。**氏名は PR依頼者に一切表示されない。** |
| `FR-AUTH-07` | 店舗プロフィール登録・編集 | client | Must | 店名・所在地・ジャンル・紹介文・画像・連絡先。投稿者には表示される（案件詳細で必要なため）。 |
| `FR-AUTH-08` | 退会 | creator / client | Must | 進行中の案件・応募がある場合は退会不可（先に完了またはキャンセルが必要）。 |
| `FR-AUTH-09` | 年齢確認 | creator | Must | 生年月日から 18 歳未満を登録拒否（`OI-08` の決定に依存）。 |
| `FR-AUTH-10` | 運営アカウントの多要素認証 | admin | Should | TOTP による MFA。管理画面の実装形態に依存（`OI-15`）。 |
| `FR-AUTH-11` | 利用規約・プライバシーポリシーへの同意 | creator / client | Must | 登録時に同意必須。同意日時と規約バージョンを記録する。文言は**役割別**に出し分け、どちらにも**当事者間のトラブル・損害について運営が責任を負わない旨の免責**を必ず表示する（`consent_terms.dart`）。 |
| `FR-AUTH-12` | 運営によるアカウント停止・解除 | admin | Must | 停止理由を記録し、対象ユーザーに表示する。 |

## 5-3. SNS：SNS アカウント連携

| ID | 機能 | ロール | 優先度 | 概要・受入条件 |
|---|---|---|---|---|
| `FR-SNS-01` | Instagram 連携の開始 | creator | Must | アプリ内から OAuth 認可画面へ遷移する。**連携前にビジネス／クリエイターアカウントへの切り替え手順を案内**する画面を挟む。 |
| `FR-SNS-02` | OAuth コールバック処理 | system | Must | 認可コードを **Edge Function 側で**トークンに交換し、暗号化して `private` スキーマに保存。**クライアントにトークンを渡さない。** |
| `FR-SNS-03` | アカウント種別の検証 | system | Must | 連携直後にアカウント種別を判定し、個人アカウントの場合はエラーメッセージと切り替え手順を提示して連携を完了させない。 |
| `FR-SNS-04` | 連携解除 | creator | Must | 解除時に当該 SNS のトークンと**インサイトデータを削除**する（`FR-INS-13`）。進行中の案件がある場合は警告する。 |
| `FR-SNS-05` | トークン失効の検知 | system | Must | バッチ実行時に認可エラーを検知したら、連携ステータスを「要再認可」に更新する。 |
| `FR-SNS-06` | 再認可の導線 | creator | Must | 「要再認可」状態ではホーム最上部に常時バナーを表示し、1 タップで再認可を開始できる。 |
| `FR-SNS-07` | 長期トークンの自動更新 | system | Must | 有効期限が近づいたトークンをバッチで自動リフレッシュする。 |
| `FR-SNS-08` | 連携直後の初回インサイト即時取得 | system | Should | 翌日のバッチを待たずに取得キューへ投入する（`OI-24`）。連携直後に全案件がモザイクのままだと離脱するため。 |
| `FR-SNS-09` | TikTok / YouTube 連携 | creator | Could | 初期スコープ外（`OI-02`）。DB は複数 SNS 前提で設計する。 |
| `FR-SNS-10` | 連携アカウントの一覧表示 | creator | Should | 連携中の SNS・最終同期日時・ステータスを表示する。 |

## 5-4. INS：インサイト取得・集計・マッチング判定

| ID | 機能 | ロール | 優先度 | 概要・受入条件 |
|---|---|---|---|---|
| `FR-INS-01` | 日次バッチの起動 | system | Must | `pg_cron` が 1 日 1 回 Edge Function を起動する。実行時刻は負荷の低い深夜帯とする。 |
| `FR-INS-02` | メディア・インサイトの取得 | system | Must | 連携済みアカウントのメディア一覧とインサイトを取得し、生データを `private` に保存する。 |
| `FR-INS-03` | レート制限スロットリング | system | Must | 全ユーザーを同時に処理せず、プラットフォームのレート制限（Instagram：200 req/ユーザー/時）を超えないよう分散実行する。 |
| `FR-INS-04` | 失敗時のリトライ | system | Must | 一時エラー・レート制限は指数バックオフでリトライキューに登録する。**バッチ全体を失敗させない**（1 ユーザーの失敗が他に波及しない）。 |
| `FR-INS-05` | 集計値の算出 | system | Must | 直近 7 / 30 / 90 日の平均値（リーチ・保存数・いいね・コメント・シェア・再生数）を再計算して保存する。 |
| `FR-INS-06` | エンゲージメント率の算出 | system | Must | 定義：`(いいね + コメント + 保存 + シェア) ÷ リーチ`。定義は 9章で確定。 |
| `FR-INS-07` | オーディエンス属性の取得 | system | Should | 性別・年齢帯・地域の分布。本人認可時のみ取得可能。 |
| `FR-INS-08` | 投稿頻度の算出 | system | Should | 直近 30 日の投稿本数。 |
| `FR-INS-09` | 投稿者本人によるインサイト閲覧 | creator | Should | **自分の**インサイトのみ RPC 経由で閲覧できる。自己分析の価値を提供し、連携継続の動機とする。 |
| `FR-INS-10` | 条件合致判定 | system | Must | 投稿者 × 案件の組み合わせで条件合致を判定する RPC。**boolean のみ返す**。 |
| `FR-INS-11` | 該当人数のカウント | client | Must | 条件式に対する該当投稿者数を返す RPC。**5 人未満の場合は実数を返さず「5人未満」を返す**（二分探索攻撃の防止）。 |
| `FR-INS-12` | バッチ実行結果の記録と監視 | admin | Should | 実行日時・成功件数・失敗件数・失敗理由を記録し、失敗率が閾値を超えたら運営に通知する。 |
| `FR-INS-13` | 連携解除・退会時のインサイト削除 | system | Must | 当該ユーザーの生データ・集計値・トークンを削除する。ただし**成果レポートの匿名集計に必要な最小限の値**の扱いは 10章で規定する。 |

## 5-5. CMP：案件作成・管理

| ID | 機能 | ロール | 優先度 | 概要・受入条件 |
|---|---|---|---|---|
| `FR-CMP-01` | 案件の作成 | client | Must | 以下 `FR-CMP-02`〜`FR-CMP-11` の項目を入力して公開する。 |
| `FR-CMP-02` | 店舗情報の入力 | client | Must | 店名・所在地・ジャンル・紹介文・画像。プロフィールから初期値をコピーできる。 |
| `FR-CMP-03` | 無償提供内容の入力 | client | Must | 提供する商品／サービスの内容と**想定価格**（並び順に使用）。 |
| `FR-CMP-04` | 投稿者条件の設定（AND / OR） | client | Must | インサイト指標（5-4 の集計値）を用いた条件式を **AND / OR の組み合わせ**で構築できる。 |
| `FR-CMP-05` | 該当投稿者数のリアルタイム表示 | client | Must | 条件を変更するたびに該当人数を再取得して表示する（`FR-INS-11`）。デバウンスして呼び出し回数を抑える。 |
| `FR-CMP-06` | 応募期間・投稿期間の設定 | client | Must | 応募期間の終了は投稿期間の開始以前であること。 |
| `FR-CMP-07` | 募集人数の設定 | client | Must | 1 以上の整数。マッチングフローの分岐条件になる。 |
| `FR-CMP-08` | ジャンルの選択 | client | Must | 飲食・美容 等のカテゴリマスタから選択する。 |
| `FR-CMP-09` | 指定ハッシュタグの設定 | client | Must | 任意のタグを追加できる。**広告表記タグ（`#PR` 等）は削除不可のタグとして自動付与**する（ステマ規制対応、`OI-04`）。 |
| `FR-CMP-10` | 必須投稿内容の入力 | client | Must | 訴求ポイント・掲載必須事項をテキストで記述する。 |
| `FR-CMP-11` | 画像のアップロード | client | Must | 店舗・商品画像を複数枚。Supabase Storage に保存する。 |
| `FR-CMP-12` | 下書き保存 | client | Should | 公開前の案件を保存できる。 |
| `FR-CMP-13` | 案件の編集・取り下げ | client | Must | **応募が 1 件以上入った後は、投稿者条件・募集人数・期間を編集できない**（公平性のため）。取り下げは応募者への通知を伴う。 |
| `FR-CMP-14` | ジオコーディング | system | Must | 所在地から緯度経度を算出して保存する。距離検索に使用（`OI-09`）。 |
| `FR-CMP-15` | 案件の複製 | client | Could | 過去案件をテンプレートとして複製する。 |
| `FR-CMP-16` | 条件テンプレート | client | Could | よく使う条件式を保存して再利用する。 |

## 5-7. APP：応募・選考・マッチング

| ID | 機能 | ロール | 優先度 | 概要・受入条件 |
|---|---|---|---|---|
| `FR-APP-01` | 案件への応募 | creator | Must | 条件合致かつ SNS 連携が有効な場合のみ応募できる。応募時にひとことメッセージを添えられる。 |
| `FR-APP-02` | 応募時の条件再判定 | system | Must | 応募リクエストを受けた時点でサーバー側が再度合致判定を行う。合致しなければ拒否する。 |
| `FR-APP-03` | 即マッチング | system | Must | **応募者数 ≦ 募集人数**の場合、応募と同時にマッチング成立とする。 |
| `FR-APP-04` | 選考モードへの移行 | system | Must | **応募者数 > 募集人数**の場合、応募期間終了時に選考モードへ移行し、PR依頼者に通知する。 |
| `FR-APP-05` | 追加条件による絞り込み | client | Must | 選考モードで、当初の条件に**追加のインサイト条件**を加えて応募者を絞り込める。**この時も個々の実数値は表示されず、絞り込み後の残り人数のみ表示**する。 |
| `FR-APP-06` | 選考の確定 | client | Must | 募集人数以内になった時点で確定する。確定しない場合の期限（`OI-30`）。 |
| `FR-APP-07` | 応募者の匿名表示 | client | Must | 応募者は**案件内で閉じた連番**（投稿者A / B / C…）で表示する。氏名・SNS アカウント名・アイコンは表示しない。 |
| `FR-APP-08` | 条件緩和案の自動生成 | system | Must | 応募期間終了時点で応募者数 < 募集人数の場合、**インサイト条件の緩和案**と**応募期間の延長案**を自動生成して PR依頼者に提示する。 |
| `FR-APP-09` | 緩和案の承認／却下 | client | Must | **PR依頼者が承認しない限り緩和は適用されない。** 却下時は現在の応募者でマッチングを成立させるか、案件を終了する。 |
| `FR-APP-10` | 緩和適用後の再募集 | system | Must | 承認された緩和条件・延長期間を案件に反映し、新たに条件合致した投稿者へ通知する。 |
| `FR-APP-11` | キャンセル申請 | creator | Must | マッチング成立後に対応できなくなった場合に理由を添えて申請する。 |
| `FR-APP-12` | キャンセル申請の承認／却下 | client | Must | **PR依頼者の承認が必要。** 承認されるとマッチングが解除され、募集枠が 1 つ戻る。却下時の扱いは `OI-31`。 |
| `FR-APP-13` | 応募の取り消し | creator | Should | マッチング成立**前**であれば投稿者が自分で取り消せる。再応募の可否は `OI-20`。 |
| `FR-APP-14` | 投稿 URL の提出と検証 | creator / system | Must | 投稿者が投稿 URL を提出し、サーバーが**本人の連携アカウントのメディア一覧と突合**して実在・指定ハッシュタグの有無を検証する（`OI-12`）。 |
| `FR-APP-15` | 案件の完了処理 | system | Must | 投稿期間終了かつ全マッチング分の投稿検証が済んだら案件を完了にし、成果レポートを公開可能にする。 |

## 5-8. MSG：メッセージ

| ID | 機能 | ロール | 優先度 | 概要・受入条件 |
|---|---|---|---|---|
| `FR-MSG-01` | チャットの開通 | system | Must | **マッチング成立時に 1対1 チャットのみ**を自動開通する。グループチャットは作らない。 |
| `FR-MSG-02` | テキストの送受信 | creator / client | Must | リアルタイム受信（Supabase Realtime）。 |
| `FR-MSG-03` | 匿名表示 | system | Must | PR依頼者側の画面では投稿者を案件内連番で表示する。投稿者側には店名を表示してよい。 |
| `FR-MSG-04` | 未読件数の表示 | creator / client | Should | 一覧・タブにバッジ表示。 |
| `FR-MSG-05` | 既読表示 | creator / client | Should | 【推奨】導入を提案。理由：来店日程の調整でレスポンス有無が重要なため。ただし投稿者に返信プレッシャーを与える副作用があるため、**送信者側にのみ「既読」を表示**し、受信者に既読を強制通知しない設計を推奨。 |
| `FR-MSG-06` | 画像の添付 | creator / client | Should | 【推奨】導入を提案。理由：来店時の待ち合わせ場所や提供商品の確認に必要。**ただし匿名性を損なう画像（顔写真・SNS 画面のスクリーンショット）の送信は規約で禁止**し、通報対象とする。 |
| `FR-MSG-07` | 通報 | creator / client | Must | 【推奨】必須で導入。理由：匿名 1対1 チャットは規約違反（直接取引の誘導、個人情報の要求、ハラスメント）の温床になりやすく、通報導線がないと運営が検知できないため。 |
| `FR-MSG-08` | 個人情報の送信警告 | system | Could | メールアドレス・電話番号・SNS アカウント名らしき文字列を検出したら送信前に警告する。匿名性維持の補助。 |
| `FR-MSG-09` | チャットの終了 | system | Should | 案件完了後 N 日でチャットを読み取り専用にする（`OI-32`）。 |
| `FR-MSG-10` | 定型文 | client | Could | 来店日程の調整など頻出のやり取りをテンプレート化する。 |

## 5-9. RPT：成果レポート

| ID | 機能 | ロール | 優先度 | 概要・受入条件 |
|---|---|---|---|---|
| `FR-RPT-01` | 成果レポートの表示 | client | Must | **投稿期間終了後**、自分の案件についてのみ閲覧できる。 |
| `FR-RPT-02` | k-匿名性チェック | system | Must | 対象人数 **n < 5** の場合は数値を返さず「人数が少ないため表示できません」を返す。 |
| `FR-RPT-03` | 代表値の表示 | client | Must | リーチ・いいね・保存・コメント・シェア等について**平均値・中央値・最小値・最大値**を表示する。 |
| `FR-RPT-04` | ヒストグラムの表示 | client | Must | 分布をグラフで可視化する。**件数が 5 未満のビンは隣接ビンへ統合**して個人特定を防ぐ。 |
