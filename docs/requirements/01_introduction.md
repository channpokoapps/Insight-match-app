# 1. はじめに

---

## 1-1. 背景

【事実】PR マッチング（インフルエンサーマッチング）市場には toridori base 等の既存サービスが存在し、店舗・企業が商品やサービスを無償提供する代わりに SNS 投稿を依頼する仕組みが一般化している。

【事実】既存サービスの多くは、投稿者の選定基準として **フォロワー数** を主要な指標としている。

【前提】しかしフォロワー数は、以下の理由で「投稿の実効性」を正しく表さない。

- フォロワーの購入・相互フォローによって水増しが可能である。
- フォロワー数が多くても、投稿がフォロワーのフィードに届いている（リーチしている）とは限らない。
- 「保存数」「シェア数」といった、店舗来訪や購買につながりやすい行動指標を反映していない。

---

## 1-2. 解決したい課題

| # | 課題 | 誰の課題か |
|---|---|---|
| P-1 | フォロワー数しか見えないため、実際には投稿が届かない投稿者に無償提供してしまい費用が無駄になる | PR依頼者 |
| P-2 | 投稿者の実力（リーチ・保存数等）を事前に検証する手段がない | PR依頼者 |
| P-3 | PR 施策の効果を、投稿後に定量的に振り返る手段がない | PR依頼者 |
| P-4 | フォロワー数は少ないが質の高い投稿をしている投稿者が、案件を獲得できない | 投稿者 |
| P-5 | 自分に合わない案件が大量に並び、応募できる案件を探すのが手間 | 投稿者 |
| P-6 | インサイトを他人に見せることへの心理的抵抗・プライバシー懸念 | 投稿者 |

---

## 1-3. 目的と提供価値

【事実】本アプリの目的は、**SNS のインサイトデータ（リーチ・保存数・エンゲージメント等）を条件として投稿者を絞り込めるようにすることで、フォロワー数では測れない「質の高い投稿者」に PR を依頼できる状態をつくる**ことである。

### 提供価値

| 対象 | 提供価値 |
|---|---|
| PR依頼者 | フォロワー数ではなく **実績値の条件**で募集をかけられる。無駄な無償提供が減る。投稿後に **匿名集計された成果レポート**で効果を振り返れる。 |
| 投稿者 | フォロワー数が少なくても、**質**を評価されて案件を獲得できる。**自分が条件に合致する案件だけ**が応募可能として表示されるため、案件探しの手間が減る。**インサイトの実数値は誰にも開示されない**ため安心して連携できる。 |
| 運営 | 差別化された独自価値を持つプラットフォームとして、広告・将来の手数料収益を得る。 |

### 本アプリの最大の差別化要因

【事実】**「条件としてインサイトを使えるが、実数値は誰にも見えない」**という非対称性。これは本アプリのすべての設計判断に優先する制約であり、詳細は [02_system_overview.md](02_system_overview.md) の「インサイト非開示アーキテクチャ原則」に定義する。

## 1-5. 成功指標（KPI）

【推奨】依頼者から KPI の指定はないため、以下を提案する。初期規模（数十〜数百ユーザー）を前提とした値である。合意後に【前提】へ昇格させる。

| 区分 | 指標 | 初期目標（仮） | 測定方法 |
|---|---|---|---|
| 獲得 | 登録投稿者数 | 3か月で 100 人 | DB カウント |
| 獲得 | 登録PR依頼者数 | 3か月で 20 社 | DB カウント |
| 活性 | SNS 連携完了率（登録した投稿者のうち連携まで至った割合） | 80% 以上 | イベントログ |
| 活性 | 案件あたり平均応募数 | 3 件以上 | DB 集計 |
| 中核 | マッチング成立率（案件のうち 1 人以上マッチした割合） | 70% 以上 | DB 集計 |
| 中核 | 投稿完了率（マッチング成立のうち期限内に投稿された割合） | 90% 以上 | DB 集計 |
| 品質 | 条件緩和提案の承認率 | — （観測のみ） | DB 集計 |
| 品質 | キャンセル申請率 | 10% 未満 | DB 集計 |
| 収益 | 広告収益 / 月 | — （観測のみ） | 広告 SDK 管理画面 |
| コスト | クラウドランニングコスト / 月 | 5,000 円以下 | Supabase 請求 |

> 【仮定】上記の数値目標はすべて仮置きである（`OI-21`）。

## 1-7. 用語定義

【事実】本書で使用する用語の定義は [glossary.md](../glossary.md) を唯一の定義元とする。本章では特に重要な 5 語のみ再掲する。

| 用語 | 定義 |
|---|---|
| **インサイト** | SNS プラットフォームが提供する投稿・アカウントの分析データ（リーチ、インプレッション、保存数、エンゲージメント等）。本人の OAuth 認可がある場合のみ公式 API で取得できる。 |
| **案件** | PR依頼者が投稿する募集。無償提供内容・投稿者条件・応募期間・投稿期間・募集人数等を持つ。DB 上のテーブル名は `campaigns`。 |
| **投稿者条件** | 案件に紐づく、応募可能な投稿者を絞り込むためのインサイト条件式（AND/OR の組み合わせ）。 |
| **モザイク表示** | 投稿者が条件に合致しない案件を、詳細を隠したまま存在だけ提示する UI 表現。 |
| **k-匿名性** | 集計結果から個人を特定できないようにするため、母数が k 人未満の場合は結果を非表示にする仕組み。本アプリでは **k = 5**。 |
