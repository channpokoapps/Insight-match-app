# 10. 非機能要件

【事実】本章の最優先方針は、依頼者指定のとおり **「運用保守工数とクラウドランニングコストの最小化」** である。性能・可用性の目標は、初期規模（数十〜数百ユーザー）に見合った現実的な水準に留める。

---

## 10-1. 性能（NFR-PERF）

| ID | 要件 | 目標 | 備考 |
|---|---|---|---|
| `NFR-PERF-01` | 案件一覧の表示 | 95 パーセンタイルで 1.5 秒以内 | 条件判定を含む。1 ページ 20 件 |
| `NFR-PERF-02` | 条件設定時の該当人数取得 | 95 パーセンタイルで 1.0 秒以内 | デバウンス 500ms と併用 |
| `NFR-PERF-03` | 案件詳細の表示 | 1.0 秒以内 | |
| `NFR-PERF-04` | チャットメッセージの到達 | 2 秒以内 | Supabase Realtime |
| `NFR-PERF-05` | 成果レポートの生成 | 3 秒以内 | 集計 RPC |
| `NFR-PERF-06` | 日次バッチの完了 | 対象 1,000 アカウントを 2 時間以内 | 深夜帯に実行 |
| `NFR-PERF-07` | アプリ起動（コールドスタート） | 3 秒以内 | |

【推奨】条件マッチングは `private.creator_metrics` の単一テーブルスキャンで完結する設計にしており、数千件規模ではインデックスなしでも十分高速。**早すぎる最適化はしない。**

## 10-3. セキュリティ（NFR-SEC）

### 10-3-1. 中核要件

| ID | 要件 | 実装 |
|---|---|---|
| `NFR-SEC-01` | **インサイト実数値をクライアントに到達させない** | `private` スキーマ分離＋`SECURITY DEFINER` RPC（2-4） |
| `NFR-SEC-02` | **k-匿名性の担保（k=5）** | 集計・件数の両方で 5 未満は非表示・丸め |
| `NFR-SEC-03` | 投稿者の識別情報を PR依頼者に露出しない | `alias_no` 経由のみ。`creator_id` はビュー・RPC で遮断 |
| `NFR-SEC-04` | SNS アクセストークンの安全な保管 | `private` に暗号化保存。クライアントへ渡さない（`OI-17`） |
| `NFR-SEC-05` | 全テーブルで RLS を有効化し、デフォルト拒否 | RLS 未設定のテーブルを CI で検出する |
| `NFR-SEC-06` | `service_role` キーをクライアントに配布しない | アプリには `anon` キーのみ |
| `NFR-SEC-07` | SQL インジェクション対策 | 条件式は構造化 JSON。ユーザー入力を SQL 文字列に連結しない |
| `NFR-SEC-08` | 通信の暗号化 | すべて HTTPS / TLS |
| `NFR-SEC-09` | 認証情報の保護 | パスワードは Supabase Auth 管理（ハッシュ化）。admin は MFA |
| `NFR-SEC-10` | 監査ログ | 停止措置・通報チャット閲覧を記録。アプリから削除不可 |
| `NFR-SEC-11` | 二分探索攻撃の防止 | 該当人数を 5 未満で丸める。条件変更の高頻度呼び出しをレート制限する |
| `NFR-SEC-12` | シークレット管理 | API キー・暗号鍵は環境変数／Secrets。リポジトリにコミットしない |

### 10-3-2. OWASP Top 10 への対応方針

| リスク | 対応 |
|---|---|
| A01 アクセス制御の不備 | RLS によるデフォルト拒否。**クライアント側のみの権限判定を行わない**（応募時のサーバー側再判定など） |
| A02 暗号化の失敗 | トークンの暗号化保存、TLS 必須 |
| A03 インジェクション | 条件式の構造化・許可リスト検証、パラメータ化クエリ |
| A04 安全でない設計 | 本章 10-3-1 の中核要件を設計段階の制約として固定 |
| A05 セキュリティ設定ミス | `private` スキーマの GRANT 状態、PostgREST 公開スキーマ設定を CI で検証 |
| A07 認証の不備 | Supabase Auth。admin は MFA。パスワードリセットのトークン有効期限を短くする |
| A08 データ完全性の不備 | マイグレーションのレビュー必須。本番 DB への直接変更を禁止 |
| A09 ログ・監視の不備 | バッチ実行結果・監査ログ・エラーの記録と閾値アラート |
| A10 SSRF | 投稿 URL は**外部フェッチせず**、プラットフォーム API の応答と照合して検証する |

【推奨】特に **A10** は重要。投稿検証で「提出された URL をサーバーがそのまま取得しに行く」実装にすると SSRF になる。**必ず本人のメディア一覧 API を叩いて突合する**方式にする。

### 10-3-3. 個人情報保護

| 項目 | 方針 |
|---|---|
| 取得する個人情報 | メールアドレス、氏名、生年月日、居住都道府県、SNS アカウント情報、インサイト |
| 利用目的 | マッチング条件の判定、匿名集計、サービス運営。**プライバシーポリシーに明記**（`OI-03`） |
| 第三者提供 | 行わない。PR依頼者への提供も「匿名集計」に限る |
| 保存期間 | 【推奨】インサイト生データは 90 日超過分を削除。集計値は最新のみ保持 |
| 削除請求 | 退会・連携解除で該当データを削除（`OI-36`） |
| 越境移転 | BaaS のリージョン選択に依存。**東京リージョンを選択**することを推奨 |

【推奨】`OI-36`（退会時のレポート整合性）については、**過去案件の成果レポートは「集計済みスナップショット」として保存**し、個人の生データを削除してもレポートが壊れない設計を推奨する。スナップショットは k-匿名性を満たした集計値のみを含むため、個人情報を含まない。

## 10-5. 保守性・運用性（NFR-OPS）

| ID | 要件 | 内容 |
|---|---|---|
| `NFR-OPS-01` | 単一コードベース | Flutter で Android / iOS / 管理画面 Web を共通化 |
| `NFR-OPS-02` | DB 変更はマイグレーションのみ | `supabase/migrations/` に集約。本番への直接変更を禁止 |
| `NFR-OPS-03` | 環境の再現性 | `supabase db reset` でローカル環境を完全再構築できる |
| `NFR-OPS-04` | 監視 | 日次バッチの成功／失敗、要再認可ユーザー数、エラー率 |
| `NFR-OPS-05` | アラート | バッチ失敗率 10% 超過、バッチ未実行、認証エラー急増 |
| `NFR-OPS-06` | ログ | 個人情報・トークン・**インサイト実数値をログに出力しない** |
| `NFR-OPS-07` | バックアップ | 日次自動バックアップ。復旧手順を文書化し、年 1 回はリストア訓練 |
| `NFR-OPS-08` | 依存の更新 | Dependabot 等で依存を定期更新 |

【事実】`NFR-OPS-06` は見落としやすい。**デバッグログに `creator_metrics` の中身を出力すると、ログ閲覧権限を持つ者に実数値が漏れる。** ロギング時は指標の値をマスクする共通ヘルパーを用意する。

## 10-6. テスト方針（NFR-TEST）

| ID | 要件 | 内容 |
|---|---|---|
| `NFR-TEST-01` | **権限テストを必須とする** | `authenticated` ロールで `private.*` を SELECT すると失敗することを自動テストで検証 |
| `NFR-TEST-02` | RLS テスト | 各テーブルについて「他人の行が見えないこと」を検証 |
| `NFR-TEST-03` | k-匿名性テスト | n=4 で非表示、n=5 で表示になることを検証 |
| `NFR-TEST-04` | 件数丸めテスト | 該当人数 4 のとき実数が返らないことを検証 |
| `NFR-TEST-05` | 匿名性テスト | PR依頼者向け API のレスポンスに `creator_id`・氏名が含まれないことを検証 |
| `NFR-TEST-06` | 条件式検証テスト | 許可リスト外のキー・演算子が拒否されることを検証 |
| `NFR-TEST-07` | ユニットテスト | Flutter のドメインロジック、Edge Function の集計ロジック |
| `NFR-TEST-08` | CI | PR ごとに `flutter analyze` / `flutter test` / DB マイグレーション適用＋権限テストを実行 |

【推奨】`NFR-TEST-01`〜`05` は**本アプリの存在意義に直結する**ため、これらが落ちた場合は他のテストが通っていてもマージを禁止する。
